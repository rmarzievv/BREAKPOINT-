## How DCC decides an implementation is "covered" (`coveragecalculator.py`)
- `build_implementation_rows` (~line 1427): an implementation step is covered if
  1) the rule's ATT&CK tag equals the implementation's technique **and**
  2) the rule's data component (from logsource/fields) intersects the step's data component.
- Rule field values (`Image|endswith`, `CommandLine|contains`) play **no part** in coverage.
- `build_implementation_coverage_rows` (~line 1555): an implementation is `covered=yes` if **at least one** step is covered.
- Mismatch with the docs: `implementationcoverage.rst` promises to assess "what behavior the analytic actually observes", not tags.
